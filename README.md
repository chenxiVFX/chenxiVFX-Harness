# chenxiVFX Harness（最小原型）

Windows 优先、中文交互的 AI 编程命令行工具。当前版本包含离线模拟模型、工作区持久化运行配置、DeepSeek OpenAI 兼容 Chat Completions 适配、受限多轮工具调用、工作区文件读取与目录列表、经逐次批准的文件写入、可审阅的精确多文件变更集、差异预览和恢复、文件引用、可审阅的结构化计划、本地会话存档、可审核的上下文压缩、Token 估算和受限只读子代理。

这不是 Claude Code 或 Codex CLI 的完整复制品。功能状态和后续清单见[功能矩阵与可恢复任务清单](ROADMAP.md)，架构边界见[架构说明](ARCHITECTURE.md)。

## 环境与安装

需要 Python 3.11 或更新版本。交互式 TTY 使用固定版本的 `prompt-toolkit` 与 `wcwidth`；核心 provider、工作区与审批逻辑仍使用 Python 标准库。Windows PowerShell 中，在仓库目录运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\cvfx-harness.exe --help
.\.venv\Scripts\cvfx-harness.exe --workspace . --provider mock
```

无需激活虚拟环境或修改 PowerShell 执行策略。启动后可输入 `你好` 测试中文交互，再输入 `/退出` 结束；`mock` 模式完全离线，不读取密钥，也不会发送网络请求。安装后可运行自检：

```powershell
.\.venv\Scripts\python.exe scripts\selfcheck.py
```

也可以直接用当前 Python 启动仓库中的脚本：

```powershell
.\run.ps1 --help
.\run.ps1 --workspace . --provider mock
```

安装后可运行 `cvfx-harness --workspace . --provider mock` 或 `python -m cvfx_harness`。默认提供商为 `mock`，不会读取密钥或发起网络请求。双向 TTY 默认启动全屏中文界面；非 TTY、`TERM=dumb` 或 `--plain` 使用原纯文本 CLI。

### 交互式终端

输入区固定在底部，上方保留会话输出；新文本会跟随到底部，手动向上滚动后不会被新输出拉回。行首输入 `/` 会在输入提示上方的专用行区筛选中文命令，终端高度不足时裁剪候选项并保留输入提示/状态栏。↑/↓ 选择，Tab 填入，Enter 提交输入；Esc 先关闭建议，再取消当前输入。`/模式 ` 只补全固定选项。输入文件引用时，TUI 可按工作区相对路径建议安全的文件和目录名称；补全有扫描/结果上限，只显示名称与类型，不读取正文、不批准读取。敏感、内部、链接和硬链接项不会显示。

空会话在输出区中央显示两行简短引导，首条输入提交后收起。界面用统一的青绿色强调品牌、输入焦点与当前选择；候选简介使用低对比辅助色，状态栏只保留当前关键操作，并按窄终端宽度缩短。

顶栏会按终端宽度缩短 provider/model 和工作区路径；`/状态` 可查看完整提供商、模型与工作区。补丁差异对新增/删除行使用高对比颜色，同时保留统一 diff 的 `+`/`-` 标记；设置 `NO_COLOR` 时不输出配色，标记仍可辨认。常见 `COLORFGBG` 浅色背景会切换到浅色主题。窄窗不会添加占位装饰。

Enter 提交当前输入，Ctrl+J 插入换行；TUI 生成期间会暂停输入，Ctrl+C 取消当前请求，不会吞掉后台输入草稿。空闲时 Ctrl+C 首次清空草稿，再次按下会取消当前输入或请求。审批面板显示精确动作和 diff，单次操作默认拒绝；“当前”会写在按钮文字中，↑/↓、Tab 或鼠标可选择按钮，并同步审批焦点，再按 Enter 确认。审批不接受文字或多行粘贴，Esc 取消。点击建议只会填入候选，点击审批选项只切换选择，不会执行动作。按钮文字同时标记选择状态，因此无色终端也能辨认。不会保存输入历史或审批答案，也没有永久授权模式。

输入 `/快捷键`（别名 `/按键`）可查看当前工作区映射。`/配置 编辑` 可暂存、审阅并确认最多 4 个映射，例如 `F2=帮助,F4=状态`；动作限于中文命令 `/帮助`、`/命令`、`/状态`、`/配置`，每个动作和按键各只能绑定一次。仅支持无修饰键 F2–F8；Enter、Esc、Ctrl+C、Ctrl+D、Tab、方向键、翻页键及退出通道不会被覆盖。映射只在空白的普通 TUI 输入提示里填入只读命令草稿，仍须按 Enter 提交；不会发起模型请求、工具调用或审批。保存后下次启动 TUI 生效。纯文本 CLI 不拦截 function keys，直接输入中文命令；TUI/CLI 的 Tab 补全和已有方向键导航仍按各自界面工作。按键是否送达由终端及 prompt_toolkit 键盘协议决定；若终端不报告某个 F 键，可直接使用对应命令。

启用 TTY 全屏渲染后，终端的 Unicode 字符宽度、鼠标能力与输入法组合仍取决于宿主。当前项目在 CI 中使用 prompt_toolkit 的合成输入和 Linux PTY 验证键位、布局启动/退出；Windows runner 使用其 Win32 输入模拟验证。尚未完成 Windows Terminal、PowerShell/ConPTY 和各中文 IME 组合的人工兼容验收。

查看[离线 Linux PTY 合成会话录屏](evidence/tui-synthetic-session.cast)和[本轮 TUI 证据说明](evidence/README.md)。录屏沿配置审阅、长中文对话、问卷取消/修改/提交与隐私选择、计划步骤确认、两文件一次审批、失败补偿及冲突留存、会话保存/恢复、压缩预览拒绝和窄终端布局走了一遍；关键帧保留各自原始分辨率。它不代表 Windows Terminal、PowerShell/ConPTY 或中文输入法的人工兼容验收。

### Windows 独立程序试验

仓库的 `Windows standalone packaging experiment` Actions 工作流会在 Windows x64 runner 上构建一个含 Python 运行时的单文件 `.exe`，随后在不依赖系统 Python 的子进程环境中检查 `--help`、离线 Mock 中文交互、含中文/空格的工作区路径，以及 EXE 驱动的合成 unittest/pytest profile。Harness 单文件本身无需系统 Python；运行用户测试时，profile 必须另行选择一个外部 Python 绝对路径，pytest 也必须已安装在该外部解释器中。Harness 不会安装 Python 或 pytest，也不会把 pytest 打进包。构建工具仅用于 CI，版本和 Windows 轮子哈希锁定在 [`packaging/windows-build-requirements.txt`](packaging/windows-build-requirements.txt)；pytest 验证依赖单独锁定并只用于开发 CI 的合成测试。

从对应 Actions 运行页面下载 `windows-x64-cvfx-harness-py312` 文件，解压后可运行 `cvfx-harness.exe --help` 或 `cvfx-harness.exe --workspace . --provider mock`。单文件启动时会把依赖解压到系统临时目录，启动会比源码或目录包慢一些，且需要临时目录可写。包中包含可执行文件、中文说明、第三方许可证通知和 SHA-256 校验文件；CI 构建不打包仓库文档、配置或工作区文件。构建与自检仅使用 Mock 和合成输入，不连接真实模型。这个未签名包只是试验，不是正式发布；Windows 可能显示 SmartScreen 或 Defender 提示，请保持系统保护开启并遵循组织策略。Actions 文件保留 14 天，不上传到发布页或包注册表。

从下载、核对 SHA-256、离线启动、配置非敏感模型设置，到单次文件审批、运行 Python 测试、保存会话并退出的首次使用流程，见[Windows 单文件包快速入门](QUICKSTART-zh-CN.md)。包内的 `README-standalone-zh-CN.txt` 也包含可独立阅读的精简步骤。

## 可用命令

在交互提示符输入 `/帮助` 查看完整说明。

| 命令 | 用途 |
| --- | --- |
| `/命令` | 列出可用中文命令；`/帮助` 显示参数与交互说明 |
| `/状态`、`/配置` | 查看有效设置及来源；`/配置 编辑` 可暂存、审阅并确认提供商、模型、端点、预算和 TUI 快捷键 |
| `/项目说明 [文件名]`、`/项目说明 清除` | 本地预览并确认根目录 `AGENTS.md` 或明确指定的项目说明；查看 `/状态` 中确认和实际请求版本 |
| `/快捷键`、`/按键` | 查看当前工作区 F2–F8 映射及纯文本 CLI 差异 |
| `/模式 计划`、`/模式 执行` | 计划模式会阻止工具写入、变更集恢复与撤销；执行模式仍逐次询问 |
| `/目标 <内容>`、`/目标 清空` | 设置或清除仅作为上下文的会话目标 |
| `/计划 生成 [需求]`、`/计划 修订` | 生成、审阅和编辑最多 3 条候选步骤、完成条件与建议工具；候选不会自动保存或执行 |
| `/计划 接受|拒绝`、`/计划` | 接受候选后保存为当前计划，或丢弃候选；查看各步骤和状态 |
| `/计划 添加 <步骤>`、`/计划 执行 <编号>` | 手工添加或确认后执行一步；每个工具仍逐次审批 |
| `/继续 <编号>`、`/继续 核验 <编号>` | 复核工作区后显式继续中断步骤；工具结果不确定时先核验 |
| `/计划 完成|阻塞|取消|重试 <编号>`、`/计划 清空` | 更新步骤状态或清除计划；结果未知的步骤不能直接重试 |
| `/保存 [名称]`、`/恢复 <名称>`、`/会话` | 保存安全对话、确认后恢复、列出工作区会话；TUI 输入 `/恢复 ` 后可用 Tab/方向键选择会话 |
| `/检查点 <名称>` | 手写进度摘要，经脱敏预览和确认后保存；不自动收集工具结果 |
| `/压缩 [保留轮数]`、`/压缩 撤销` | 预览哪些历史会概括、合并或整轮丢弃；确认后应用，可恢复尚未继续对话的内存检查点 |
| `/统计`、`/预算 [tokens]` | 分开展示本地上下文估算、提供商 usage 与缓存命中字段；`/预算` 临时设置本地估算阈值 |
| `/测试 列表|添加|运行|移除` | 管理固定 Python `unittest`/`pytest` 测试目标；添加时用户独立选择外部 Python，模型只能选择可运行配置的 ID |
| `/子代理 提交 [--读取 路径 ... --] 任务甲 \| 任务乙` | 每项单独批准后提交最多 3 个隔离子任务；最多 4 个精确只读路径 |
| `/子代理 列表 [编号]` | 查看子任务状态和本会话共享预算 |
| `/子代理 取消 <编号>` | 取消排队或运行中的子任务 |
| `/子代理 收取 [编号\|全部]` | 将终态结果汇总为不可信上下文加入主对话 |
| `/子代理 时限 <秒>` | 设置之后提交的子任务运行时限，范围 5–120 秒 |
| `/变更集 列表`、`/变更集 证据`、`/变更集 恢复 <编号>` | 列出未完成批次和孤立备份证据；恢复需单独预览确认，只恢复仍匹配本批写入的文件；启动时不会自动处理 |
| `/撤销` | 预览并确认恢复最近一次 Harness 文件写入 |
| `/多行` | 逐行撰写一个问题；单独输入 `/提交` 发送，`/取消` 或 Ctrl+C 丢弃 |
| 模型澄清问卷（按需） | 信息不足时模型可一次询问 1–3 个非敏感问题；回答只补充本轮上下文，不产生任何授权 |
| `/退出` | 结束会话 |

`/多行` 以换行合并文本，最多 64 KiB UTF-8；只有单独一行 `/提交` 会发送。无 TTY 时可直接把命令和多行块逐行写入 stdin；EOF 会结束会话，未结束的多行块会丢弃。Harness 不保存输入历史或审批回答。纯文本模式不做补全。交互 TUI 补全固定中文命令、固定枚举、安全工作区相对路径、本地会话名，以及 `/测试 运行 ` 和 `/测试 移除 ` 后的本地配置 ID。运行补全仅列可运行配置；移除补全会标注需重新选择解释器的旧配置。路径和会话名建议最多扫描 1000 个目录项、显示 50 个候选，不读取会话内容。Tab 只填入选择，按 Enter 提交命令；鼠标只选择，不会自动提交。恢复的是经过校验的历史上下文，旧审批和运行授权不会恢复，旧工具调用不会执行；替换已有上下文前仍需确认。文件路径和测试配置补全不会执行命令，也不会批准动作。

模型在信息不足时可调用结构化 `ask_user`，每次最多提 3 个简短问题，可附建议答案；建议只填入草稿，用户始终可以自由作答。TUI 按题编辑，支持多行、逐题切换和回答审阅；只有显式按“提交回答”后才回到本轮模型。纯文本界面可输入建议编号或自由回答，并在确认后提交；`/多行` 可录入多行回答。直接空行是明确的空回答。问卷内 Esc 或“取消提问”会把“已取消、没有回答”的结构化结果交给本轮模型；Ctrl+C 则取消整个模型请求并回到正常输入。模型必须把取消当作没有信息，不能猜答案。

问题与答案有字段、大小、字符和凭据样式检查；疑似询问密钥、密码、Token 或凭据会在打开问卷前被阻止，疑似凭据答案不会发回模型。TUI 不把问题草稿和回答写入对话 transcript、输入历史或剪贴板。每份问卷默认“仅本次”；提交前用户可明确选择“允许本地保存”，只有执行 `/保存` 后才把普通问答写入该工作区会话。如果此前已有未存档回答、文件引用、敏感内容或工具结果，当前问卷会明确显示不能存档，并阻止选择本地保存，避免把依赖此前私有上下文的澄清带入会话。没有选择保存时，问卷回答及受其影响的后续轮次会从存档中省略；`/状态`、`/保存` 与 `/恢复` 会显示省略类别和恢复后可能需要重新提供的提示。压缩时仅保留已明确同意本地保存的问卷内容，默认仅本次的回答不会进入摘要。答案只是本轮不可信上下文，不能批准读取、修改、测试或其他操作。计划模式可提问；只读子代理不能提问，信息不足时会回报限制并请主会话补充。

`/测试 添加 <ID>` 会逐项询问框架、外部 Python 可执行文件绝对路径、工作目录和目标路径，支持中文及空格路径。解释器必须是现存普通可执行文件；配置保存在 `.harness/config/test_profiles.json`，模型文件工具不能读取或修改。配置只包含用户选择的解释器、固定框架和工作区相对路径，不接受 argv、shell 命令或模型提供的路径。旧配置没有解释器时保持禁用，用户可重新录入同一 ID。没有配置时 `/测试 列表` 会显示逐步创建方式；过期解释器、缺少 pytest 和用户取消也会显示恢复提示。pytest 不属于 Harness 运行依赖，Harness 不会自动安装它；用户需在所选外部 Python 环境中自行准备依赖，或使用标准库 `unittest` 配置。只有用户明确要求运行测试时，模型才能选择已通过路径校验的配置 ID；`/测试 运行 <ID>` 可由用户直接发起本地测试。运行固定为外部解释器的 `-m unittest discover -s <目标>` 或 `-m pytest -q <目标>`；每次执行前展示确切解释器、argv、工作目录、120 秒时限、32 KiB 合并输出上限，并逐次审批。直接 CLI 输出只留在本地；模型工具分享输出仍需单独审批。一次提问至多启动一个测试进程。

测试代码以当前用户权限运行，不是沙箱；网络访问没有被屏蔽，工作区路径检查也不能限制测试代码访问用户可访问的其他资源。子进程不会继承凭据或其他运行时环境变量；Windows 仅传递系统路径和临时目录。Linux 使用独立进程组，对普通子进程取消/超时会终止该组，但自行 `setsid` 脱离的进程不保证被捕获；Windows 在挂起进程状态下先分配 kill-on-close Job Object，再恢复运行。测试输出先在本地展示，做凭据样式脱敏和终端控制字符转义；是否将最多 16 KiB 脱敏输出发送给模型会另外逐次确认。拒绝分享时模型只收到测试状态和退出码。工具结果视为不可信内容，不写入会话存档。

测试 profile 工具复用 Agent 的现有工具循环。OpenAI 兼容 SSE fixture 验证工具增量完整结束并通过协议校验后，才进入逐次审批；Mock 不模拟模型工具调用；通过 Agent 明确请求 SSE、但 provider 没有 `complete_streaming` 时会直接报错。

在提问里用 `@相对路径` 引用文件；路径含空格时写 `@{资料/需求 文档.txt}`，多行问题中也可使用。TUI 中输入 `@{资料/需` 后按 Tab 可选中文件或目录；目录补全后继续输入，文件补全会补上 `}`。不含空格的名称也支持 `@资料/READ`。补全只列安全名称，不读取文件正文；选中的文件仍需单独批准后才读取，内容随后会发送给所选提供商。模型也可请求逐次确认的目录列表，列表只包含名称与类型，不读取条目正文。

项目说明是显式选择的可选上下文。`/项目说明` 只在当前工作区根目录查找 `AGENTS.md`；若不存在，会列出安全的根目录文本文件名供选择。也可用 `/项目说明 README.md` 指定一个根目录 `.md`、`.markdown`、`.rst`、`.txt` 或 `.adoc` 文件。Harness 会复用工作区路径、敏感文件、链接/硬链接、普通文件、UTF-8 和 64 KiB 检查；不会扫描主目录、父目录或其他工作区。命令先显示本地预览、准确字节数和 SHA-256，再询问是否确认；拒绝不会替换此前仍有效的确认版本。确认后，文档作为不可信项目背景加入主会话后续请求，计划模式同样适用，不会自动传给子代理。

`/状态` 显示当前确认文件的路径、字节数和摘要，以及最近一次 provider 调用的请求上下文实际包含的文件版本；同时说明变化、替换、安全检查失败、手动清除或进程退出时的失效规则。每次 provider 请求前都会重新读取并比对文件内容和身份/元数据；若发生变化，请求会停止，必须重新预览并确认，不会静默刷新。文档不能改变安全规则、扩大审批、要求执行程序或授予额外工具权限。确认只在当前进程内有效；文档原文不会写入会话存档、压缩摘要或子代理上下文。

模型还可用 `search_text` 在已选工作区目录下查找固定字面量，例如中文代码符号或注释；这是区分大小写的纯文本子串，不执行正则表达式。可按相对目录和文件 glob 缩小范围（glob 相对所选目录；无斜杠时匹配任意层级的文件名），并遵循目录链上的 `.gitignore` 规则。每次搜索前都会展示查询、范围和扫描上限并单独审批；拒绝时不读文件。每次最多扫描 5000 个目录项、500 个目录（递归深度 64）、2000 个文件、8 MiB 和 5 秒，单文件上限 64 KiB；最多返回 100 个匹配行片段、每条 240 字符、总结果 32 KiB。路径 glob 中 `*` 不跨目录分隔符，`**` 可跨层级；敏感目录/文件、Harness 内部状态、链接、硬链接、二进制、非 UTF-8 与超大文件会跳过；无法安全解析 `.gitignore` 时停止搜索。若选择的目录本身被 `.gitignore` 排除，结果会明确说明未扫描。结果只含工作区相对路径、行号和脱敏片段，并作为不可信数据返回；搜索批准不授权其他读取、写入或运行操作。EOF 时文件、目录与搜索审批默认拒绝。敏感路径、工作区外路径、链接逃逸和非 UTF-8 文本默认拒绝。当前没有 shell 执行工具，PowerShell/cmd 命令不会执行。

### 整批多文件精确修改

用户明确要求一次协调修改多个文件时，模型可提出 `apply_change_set`：每批 2–5 个现有 UTF-8 文件，每个文件提供原文件 SHA-256 和唯一、非空的精确旧文本替换。不会新建文件或目录、删除、重命名或改用整文件覆盖。路径、敏感内容、全部版本和精确匹配会先整体校验；输入不超过 96 KiB、完整 diff 不超过 128 KiB、原文件备份合计不超过 256 KiB。审批一次展示每个路径、原文件短哈希和滚动完整 diff，默认拒绝；拒绝、预检失败或确认后的版本过期均不会由本工具开始任何写入。

批准后按规范路径顺序逐文件写入，并在每次前复核版本。中途失败或取消会停止后续写入，然后逆序尝试恢复仍精确匹配该批写入版本的文件；外部有变化的文件标记为冲突并保持不动。返回每个文件的已改、已恢复、未改、失败或冲突状态，不把部分结果说成全部成功。变更日志和原始备份留在模型工具不可访问的 `.harness/change-sets/` 与 `.harness/backups/`；程序启动会核对批次状态与逐文件状态，并扫描最多 2048 个备份条目，发现孤立批次备份、关联矛盾、损坏项或扫描未完成时会明确提示，绝不把这些情况说成“没有待办”。终态日志超过 32 条时会逐步清理；清理进度可在后续启动核对时安全续跑，原始备份仍保留供单文件撤销使用，清理不会改动工作区文件。未完成批次的日志/备份关联仍须完整匹配。启动不自动恢复、重放或沿用审批。`/变更集 证据` 只读显示安全的本地元数据；缺失的批次日志不会从备份重建授权。用户运行 `/变更集 恢复 <编号>` 后，本地会重新检查状态并展示完整恢复差异；只有另外明确确认后，才会尝试安全恢复。

这不是跨文件事务：进程或系统在批次中途退出时可能暂时留下部分改动，用户需审阅恢复预览。每个底层文件替换也仍有最后版本检查到原子替换之间的窄竞态窗口；Harness 不宣称 CAS 或阻止无视锁的外部编辑器。摘要、历史确认和模型的工具调用都不会产生新的授权；计划模式会拦截变更集，子代理没有此工具。

## 工作区配置

运行设置保存在工作区 `.harness/config/settings.json`，模型文件工具无法读取。配置只接收非敏感字段，不接受 API Key 或其他凭据。Harness 不会为任意工作区修改 `.gitignore`；若项目由 Git 管理，请自行确认 `.harness/` 已被该项目忽略，避免提交本地设置或未加密会话。优先级从低到高为：内置默认值、工作区配置、`HARNESS_*` 环境变量、命令行参数。支持的环境变量为 `HARNESS_PROVIDER`、`HARNESS_MODEL`、`HARNESS_BASE_URL`、`HARNESS_TOKEN_BUDGET` 和 `HARNESS_MAX_OUTPUT_TOKENS`。

建议在 TUI 或纯文本交互中使用 `/配置 编辑`。它会先展示当前生效值和来源，再逐项收集工作区层设置，最后展示完整候选与高优先级覆盖后的生效值：

```text
/配置 编辑
提供商 [mock]（mock/openai/deepseek-anthropic）> openai
模型 [deepseek-flash]（输入 默认 使用 deepseek-flash）> deepseek-flash
Base URL [https://api.deepseek.com]（输入 默认 使用提供商默认值）> https://api.deepseek.com
本地估算上下文阈值 [16384]（1024–1000000）> 32768
输出 Token 上限 [2048]（1–65536）> 2048
TUI 快捷键 [未设置]（仅 F2–F8；帮助/命令/状态/配置；例如 F2=帮助,F4=状态；默认清空）> F2=帮助,F4=状态
确认保存这些非敏感设置？输入 是 确认，其余取消 > 是
```

逐项输入时空行保留工作区当前值；更换 provider 会把模型和端点暂设为新 provider 的默认值，之后可自定义。`默认` 清除模型或端点覆盖；快捷键字段输入 `默认` 可清空所有映射。快捷键语法只接受 F2–F8 与帮助、命令、状态、配置这 4 个本地只读动作，不支持任意命令、宏或脚本，也不接受修饰键组合；中文和对应的英文动作名均可输入。审阅前验证整个组合；确认前不会写盘，输入 `/取消`、Ctrl+C、Esc 或回答否都会丢弃草稿。保存时会核对配置文件版本；若编辑期间被其他来源修改，会保留新文件并提示重新打开编辑。`/配置` 查看本轮 provider、下次启动配置和各字段来源；`/快捷键` 查看已保存映射。快捷键下次启动 TUI 生效；纯文本 CLI 使用命令，不捕获 function keys。现有 Tab 补全、方向键导航及取消/退出通道保留。按键传输依赖终端向 prompt_toolkit 报告功能键；无法识别时可直接输入命令。原有 `/配置 提供商 ...` 等单字段命令仍可直接使用。提供商、模型和端点保存后需重启才会切换本轮 provider；本地预算和输出上限在无更高优先级覆盖时立即应用。`/预算 16384` 只改当前会话。`/配置 重置` 写回默认值，但环境变量和命令行仍优先。若配置文件损坏，可用 `--ignore-config` 忽略它启动，再通过 `/配置 编辑` 从默认值审阅并保存有效设置。

当前支持离线 `mock`、DeepSeek OpenAI 兼容模式，以及独立的 `deepseek-anthropic` DeepSeek Anthropic 兼容模式。后者固定使用 `https://api.deepseek.com/anthropic` 路径，只接受 `deepseek-flash` 与 `deepseek-v4-pro`，不会连接官方 Claude 服务，也不接受 Claude 模型别名。两种 DeepSeek provider 只读取 `DEEPSEEK_API_KEY`；Anthropic 兼容模式不会查询 `ANTHROPIC_API_KEY`。凭据仍只从环境读取，绝不写进配置文件；请求仅发往固定 DeepSeek HTTPS 主机与协议路径，不接受重定向。疑似凭据样式的聊天输入会在发给模型前拒绝，TUI 也会隐藏它的回显。不得把密钥放入 URL、命令行、项目文件、聊天或 Git。

同样的非敏感设置也可在启动时用 `--provider`、`--model`、`--base-url`、`--token-budget` 和 `--max-output-tokens` 覆盖。超长或格式错误的输入不会被错误消息回显。配置文件损坏时可这样绕过并继续使用 Mock：

```powershell
.\.venv\Scripts\cvfx-harness.exe --workspace . --ignore-config --provider mock
```

## 会话、压缩和 Token 统计

存档放在工作区 `.harness/sessions/`，为 UTF-8 JSON。`/保存` 只保存完整且安全的普通用户/助手对话、受标记的本地历史摘要、非敏感目标文本、明确同意保存的问卷回答和受控省略状态。工具调用及结果、文件引用内容、不完整轮次、疑似凭据文本不会存档；为避免助手复述工具结果，引用或工具调用后的回复也会从默认保存中排除。未保存问卷及其影响会列入存档省略状态；`/恢复` 会提示可能需要重述。新版存档记录省略类别和数量，旧版存档没有完整性元数据，无法追溯判断是否有历史省略。恢复前会先完整校验；损坏存档不会替换当前上下文。存档是本地明文文件，未加密，请勿共享含敏感内容的工作区。

如需保留这类会话的进度，可运行 `/检查点 名称`，然后手写一段摘要。Harness 不会从当前消息、文件引用或工具结果生成该摘要；已知密钥/Token 形态会先脱敏，程序展示脱敏后的确切文本并再次要求确认。检查点只保存这段摘要和 token 计数，不保存目标、原始工具输出或其他上下文。检查点恢复后仍是带不可信标记的用户消息。

`/压缩` 会逐项展示将概括的旧轮次、合并的既有摘要、整轮丢弃的旧内容、原样保留的近期轮次和将传入模型的可读摘要；用户确认后才修改上下文。摘要保留当前目标（对疑似凭据形态先脱敏）、可识别的完整用户限制，以及仅用户明确同意存档的问卷回答；未同意保存的问卷回答不会进入摘要，并会计入存档省略状态。其他旧对话只留有界短摘录，摘要最多 32 KiB UTF-8，较长历史会缩短/减少摘录，超限时拒绝压缩。最近轮次作为完整消息组保留，旧工具轮次只会整轮丢弃；遇到未完成请求或工具调用/结果配对异常时拒绝压缩。摘要始终作为带不可信标记的 `user` 消息，并明确历史审批不延续为当前授权。确认压缩后会在当前进程内保留一个恢复检查点；`/压缩 撤销` 可在成功继续对话前恢复原始轮次，之后新回答会使检查点失效。检查点不写入会话存档。系统提示和固定工具 schema 顺序保持稳定；用户测试 profile 有增删时，尾部 ID 枚举 schema 会变化。程序不声称或保证任何缓存命中率。

Token 数由本地字符启发式估算，不是提供商 tokenizer 的精确数值。`/统计` 另显示系统提示/当前工具 schema、会话消息的独立估算分项；配置的测试 profile 会加入 ID 枚举 schema。分项不相加，也不是缓存命中量。有效 provider usage 与缓存命中字段单独展示；缓存字段缺失/无效时命中量未知，不将本地前缀或估算值说成命中或节省。`--token-budget`（默认 16384）和 `/预算` 是本地估算阈值；提问发送前会检查当前输入估算并至少保留 128 tokens 生成余量，超出时不发送并提示先预览压缩或调整本地阈值。它不代表提供商上下文窗口或账户额度；是否遇到远端限制仍由提供商决定。`--max-output-tokens`（默认 2048）为单次提问的所有模型回复共享输出预算，`--max-model-requests` 可把每次提问限制为 1–4 次请求（默认 4），不会自动重试。每次请求按剩余本地余量、输出预算和剩余请求数分配 `max_tokens`。`--request-timeout` 为每个 SSE 请求设置从建连开始的总时限，默认 45 秒、硬限 120 秒。若 provider 返回 usage，统计会记录报告值；缺失时按该请求完整 `max_tokens` 额度保守扣除。字符估算不是 provider tokenizer，不能保证远端计量精确；当前不计算金额或推测动态价格。启动参数示例：`.\run.ps1 --token-budget 32000 --max-output-tokens 2048`。

委派计划每个会话最多 3 项，每项在启动前单独审批；任务最多 240 字符、最多 2 个并发子代理、每项最多 2 轮模型请求、首轮最多 2 个工具调用、单任务输出最多 256 tokens、单请求输入估算最多 512 tokens、共享输入估算最多 3072 tokens。子代理运行时限默认为 60 秒，可用 `--subagent-timeout` 或 `/子代理 时限 <5–120>` 调整；这是每项任务的硬上限，从该任务首个 provider 请求开始计时，审批与执行前排队不计入。单个 SSE 请求仍受 `--request-timeout` 限制，默认 45 秒、上限 120 秒；取消在响应读取期间最多约 250 ms 检查一次。Mock、OpenAI 兼容和 DeepSeek Anthropic 兼容 provider 共用 `complete_subagent` 边界；Anthropic 兼容路径的远端服务行为尚未在线验证。子代理默认不获文件工具；用户可用 `--读取` 明确预授权最多 4 个工作区内现存文件或目录，每次委派审批会展示精确任务、工具和时限。文件只允许 `read_file`；目录只允许列名称与类型。子代理不能读范围外路径、写入、执行 shell、递归委派，也不会继承主会话、目标、文件引用、工具结果或父代理的审批。共享输入上限用本地估算执行，失败请求会保留输入预留；获批任务的输出上限会预留、不因失败释放。结果会先脱敏，再以不可信 JSON 汇总；`收取` 将它作为不可存档的 user 上下文加入父对话。失败、超时、取消和预算耗尽会显示为不同状态。

示例：`/子代理 提交 --读取 src/app.py -- 检查路由边界 | 梳理配置校验`。如任务不需要文件，可用旧写法 `/子代理 检查路由边界 | 梳理配置校验`。提交后用 `/子代理 列表` 查询，`/子代理 取消 S01` 取消单项，`/子代理 收取 全部` 收取已结束结果。子代理文件范围必须在当前工作区内，且不递归扩展目录；需要其他文件时重新提交明确范围并再次审批。

### 用户计划步骤

`/目标` 设置的内容仍只是上下文；只有用户明确运行 `/计划 生成 [需求]` 才会请求候选。生成时只向 provider 发送一个脱敏后的目标/需求提示，并传入空工具列表；不携带会话历史、文件引用或目录内容，不读取或写入文件、不运行测试或命令。响应必须是符合严格 schema 的 JSON，最多 3 步，每步包含说明、可检查的完成条件和最多 5 个受限工具名。超限、控制字符、凭据形态、未知字段、重复 JSON 键或夹带工具调用均拒绝，原计划不变。候选只保存在当前进程内。

用户可以用 `/计划 修订 <编号> <说明|条件|工具> <内容>` 编辑候选，再 `/计划 接受` 将其存入工作区 `.harness/plans/current.json`，或 `/计划 拒绝` 丢弃。接受会替换现有计划；生成和拒绝都不改存档。v3 存档包含步骤说明、完成条件、建议工具、状态，以及固定枚举表示的最近工具阶段、结果类别和中断原因；不保存模型原始输出、工具参数、路径、文件内容、问卷答案、测试输出或审批。旧版本计划可读取迁移；因为旧格式不能区分从未开始和中断后退回待办的步骤，所有未完成旧步骤都按结果未知处理，并须逐步核验后才可启动 Agent。整个 UTF-8 存档上限 8 KiB；说明和完成条件各最多 400 字符。目标和计划都不会创建授权。

`/计划 执行 <编号>` 会先展示说明、完成条件和建议工具并要求确认。每次只启动一个全新 Agent，其中只包含脱敏后的当前目标上下文和该条步骤；最多 2 次模型请求，输出上限 512 tokens。执行仍使用现有工具层：每次读取/列目录、写入/补丁或已配置测试运行都单独批准；建议工具清单只供审阅，不会预先授权，也不扩大可用工具范围。没有 shell、任意代码、删除或子代理入口。步骤留在 `in-progress`，用户检查输出后再 `/计划 完成 <编号>`。模型/传输失败会标为 `blocked`，用户或请求取消会标为 `cancelled`；此前已批准的修改不会因取消自动回滚。

计划存档会在发出模型请求、等待工具审批、本地问卷交互、工具执行和工具结果返回等边界写入固定阶段记录。重启发现未完成步骤后会设为 `blocked`，显示已完成/待办步骤、最近工具类型、结果类别和中断原因；历史参数、目标路径和原始结果不保留。审批前中断会显示为未执行；获批后若工具结果尚未记下，则标为结果未知。未知结果不能用 `/计划 重试` 绕过，也会阻止其他步骤开始；先检查当前工作区，再用 `/继续 核验 <编号>` 明确确认后继续。旧版没有阶段记录的未完成步骤也须逐个核验，全部完成前不会启动 Agent。其他受阻/取消步骤用 `/继续 <编号>`。继续前会检查工作区路径及未完成变更集，并要求一次明确确认；确认后启动新的空白 Agent，旧调用和审批不重放，所有工具仍按当前步骤逐次审批。拒绝确认、工作区预检失败或状态冲突时不会启动 Agent。该状态说明是脱敏的阶段概述，不是原工具输出的恢复副本。每次继续仍有相同单步预算。

冷启动后，计划只保留步骤说明、完成条件、建议工具和受限阶段记录，不恢复原目标、聊天历史、问卷答案或工具结果。若当前进程没有目标，`/继续` 会让用户选择补充一条最多 4 KiB 的临时目标/约束，或仅凭已保存步骤继续；选择补充后会在最终确认中说明它将作为本次步骤的模型上下文发送，且不写入计划、主会话目标或会话存档。开始前会再次明确展示所用上下文并要求确认；空白输入也须确认按有限步骤上下文继续。若当前进程已有目标，则显示它会作为不可信上下文使用，不恢复其他历史。只有本进程明确预览确认且仍有效的项目说明会单独附加；它是不可信背景而非授权，也不会自动传给子代理。拒绝、输入取消、工作区预检失败或状态冲突时不会启动 Agent。

## DeepSeek OpenAI 兼容模式

适配器默认端点为 `https://api.deepseek.com/chat/completions`，模型默认为 `deepseek-flash`；工作区配置、环境变量和 CLI 参数可设置非敏感字段。选择 OpenAI 模式后，程序只读取 `DEEPSEEK_API_KEY`；Mock 模式不会查询这个变量。非空 DeepSeek 密钥无论来自环境还是显式覆盖，都只允许发往 `https://api.deepseek.com:443`；带认证的 OpenAI 兼容与 Anthropic 兼容请求均拒绝 HTTP 重定向，避免认证头转发到重定向目标。`/配置` 会显示变量名，不显示值；认证头不会进入模型消息、会话或 Harness 日志。HTTP 仅对本机 loopback 开放且仅供本地合成 fixture 使用；无凭据 provider 只允许 loopback。请勿把密钥放进 URL、命令行、项目文件、聊天或 Git。

本地 CLI 尚无隐藏输入界面；若直接使用普通环境变量，原值会进入 Harness 进程。若以后要在 Codex Cloud 使用 DeepSeek，用户可自行在该环境的 **Network secrets** 中添加变量 `DEEPSEEK_API_KEY`，Allowed domains 设为 `api.deepseek.com`。[Codex Cloud 官方说明](https://learn.chatgpt.com/docs/environments/cloud-environments)指出，Network secret 会以 placeholder 交给程序，并由代理在允许目标的 HTTPS 443 请求中替换原值，不把原始值放入本地进程或文件；普通 Environment variable 的值对 task 可见。保存环境改动后需要 Republish 并新建 task。网络密钥须使用自己的 Key，不能与同名直接环境变量冲突。

离线回归使用合成数据和本机 HTTP fixture。曾完成无工具连接 smoke 和受限只读目录闭环，只验证当时的认证与授权路径；测试只使用合成提示和合成目录信息，不代表完整产品或其他工具已通过。真实调用用量单独跟踪。HTTP 429 不自动重试；适配器只统计 provider 返回的 Token usage，不核算费用。直接调用保留的非流式 JSON `complete()` 时，取消信号只在发送前和收到响应后检查；CLI SSE 流在响应体读取期间每 250 ms 检查一次，建连/响应头仍受 provider 超时限制。

## DeepSeek Anthropic 兼容模式

`--provider deepseek-anthropic` 使用 DeepSeek 官方记录的 Anthropic-compatible API 入口 `https://api.deepseek.com/anthropic`，内部只请求 `/v1/messages`；模型限制为 `deepseek-flash` 和 `deepseek-v4-pro`。选择该模式时 Harness 只读取 `DEEPSEEK_API_KEY` 并通过 `x-api-key` 请求头发送，不会读取 `ANTHROPIC_API_KEY`。固定目标 HTTPS 使用标准证书校验，HTTP 重定向不会跟随。官方 Claude 服务、Claude 账号、Claude 模型别名、自定义主机和其他 API 路径均不支持。详情参见 [DeepSeek Anthropic API 指南](https://api-docs.deepseek.com/guides/anthropic_api/)；DeepSeek 文档说明了兼容功能，但没有枚举其 SSE 事件序列和 usage 响应字段，因此事件序列按[Anthropic 官方 SSE 规范](https://platform.claude.com/docs/en/build-with-claude/streaming)实现。定向远端验收只核对过一次固定合成提示的基础文本对话；工具循环和其他事件组合尚未远端验证。

请求使用 Anthropic Messages 的 `system`、文本消息、工具 schema、`tool_use` / `tool_result` 往返与 `auto` 工具选择。模型侧 thinking 默认关闭（见 [DeepSeek thinking mode 文档](https://api-docs.deepseek.com/guides/thinking_mode/)）；若响应仍含标准 `thinking` 块，Harness 不显示其内容，并在当前内存上下文中原样保留文本和签名供工具轮次使用。只接受文本、带有效签名的 thinking 和标准 `tool_use` 块；图片、多模态、`server_tool_use`、`redacted_thinking`、文档/搜索/MCP 等内容，以及未知 SSE 事件、字段或增量均明确拒绝。DeepSeek 文档列出部分这些 block 为已支持或忽略，但 Harness 当前没有对应本地执行或保真路径，因此不会静默丢弃。通过完整消息结束标记、参数 JSON 与现有 Agent 预算校验后，工具仍逐次走本地审批；只读子代理限定原有精确路径规则。Mock 不会被拿来模拟该 provider；若某个 provider 没有流式能力，CLI 会明确拒绝流式请求。

Anthropic SSE 使用与现有 provider 相同的有界 UTF-8/SSE 解析器：跨网络块处理中文和 LF/CRLF 边界，限制 4 MiB 响应、2 MiB 助手内容、512 KiB 单行/事件、16,384 个事件及最多 120 秒总时限；响应读取时约每 250 ms 检查取消。只有收到完整 `message_stop` 才返回工具调用；错误或截断响应不会触发该轮工具。标准 `input_tokens` / `output_tokens` 字段若出现会用于统计，但 DeepSeek 尚未在该兼容指南中明示这两个响应字段；usage 缺失或无效时按该请求完整 `max_tokens` 额度保守扣除，不推测缓存命中。终端输出沿用控制字符可见转义与疑似凭据脱敏；网络错误不显示原始异常、请求头、URL 或响应体。非流式 `complete()` 存在，但它仅在发送前和收到响应后检查取消，CLI 使用有界 SSE。

本地协议回归使用 loopback 合成 HTTP fixture 与离线测试。历史提交 [`5e5a9ca`](https://github.com/chenxiVFX/chenxiVFX-Harness/commit/5e5a9ca2fcc840ec19004cb96d43c1ce75e594b2) 有一次范围有限的真实 DeepSeek 合成端到端核验：在临时合成工作区经单独读取审批、核对后批准唯一的一行补丁，再运行一次合成 smoke 测试，退出码为 0；没有触碰真实项目或生成测试代码。另做过有限范围的兼容流程核对：OpenAI 兼容 SSE 对一个精确批准的合成文件执行写入并逐字节读回；只读子代理仅获准读取一个合成文件，结果被收取并加入父对话的不可信、不可存档上下文；Anthropic 兼容 SSE 完成基础合成文本对话并返回 usage。这些只证明所列单次路径，不构成当前所有 provider、所有工具组合或真实项目验收；没有把私人逐请求用量或日志放入仓库。

### 有界 SSE 流式交互

CLI 的 OpenAI 兼容模式和 DeepSeek Anthropic 兼容模式均使用有界 SSE 逐段显示中文文本；UTF-8 解码器和事件解析器可跨任意网络分块处理中文及 LF/CRLF 行界。OpenAI 兼容流要求完成状态及 `[DONE]`；Anthropic 兼容流按 `message_start`、content block、`message_delta`、`message_stop` 校验。响应上限为 4 MiB、助手文本和推理合计上限为 2 MiB、单行/单事件上限为 512 KiB、最多 16,384 个事件、总时限最多 120 秒。取消事件在响应体读取期间每 250 ms 检查一次；建连和响应头等待受 provider 超时限制。网络错误只附加固定分类、阶段、HTTP 状态、已收字节数和耗时；POSIX `ETIMEDOUT` / `EAGAIN` 和 Winsock `10060` / `10035` 均按超时阶段归类；不显示原始异常、请求头、URL 或响应体。响应由上下文管理器关闭，HTTP 状态错误也会显式关闭。

SSE 保留 Python `urllib` 的 HTTP 代理 CONNECT 和 TLS 验证路径，调用线程用 `read1()` 读取，单个 watchdog 在取消或截止时间到达时 shutdown 当前响应 socket，并在退出时停止和 join。正常生成停顿不会触发短超时后重读，真正的读取超时直接终止；未使用 `select`。若响应不提供可用于有界读取的 socket，会明确报错。建连、代理 CONNECT、TLS 和响应头仍依赖网络栈超时，取消需等这些调用返回才能检查；这些阶段不能保证与响应体同样的主动硬截止边界。离线测试通过本机 CONNECT 代理和测试专用证书检查代理隧道、TLS 主机名与证书校验、正常停顿、分块头慢滴、中文、取消与截断；测试证书只为 `sse-fixture.invalid` 使用，客户端仍要求有效证书且开启主机名检查。普通 JSON `complete()` 仍走非流式 `read()`，其取消检查只在发送前和收到响应后执行。

工具调用片段会先在内存中累积并校验，收到协议完整结束标记后才交给既有 Agent 循环；工具仍逐次审批。截断、无效或超限流不会返回不完整工具调用，因此不能触发该轮工具。当前支持 OpenAI 兼容的单候选文本、`reasoning_content` 和函数工具调用，以及 DeepSeek Anthropic 兼容的文本、签名 thinking 与标准工具块；不支持多模态、`logprobs`、未签名/未知增量和其他 Anthropic 内容块。Mock 默认离线且不使用 SSE；请求流式输出的 provider 若没有 `complete_streaming` 会明确拒绝。流式文本可能在完整状态尚未到达前已显示；取消或传输失败后不完整轮次不会写入会话，已显示片段不会自动撤回。控制字符会以可见转义显示，疑似凭据片段在终端输出前脱敏。单元与本机 fixture 测试不等于完整产品验收；Anthropic 在线证据目前只覆盖一次基础合成对话，工具轮次、thinking 和错误/取消事件仍未远端验证。

## 权限与边界

- 文件工具只接受工作区内相对路径；拒绝绝对路径、UNC、ADS、父目录遍历、敏感路径、reparse point 和可识别的硬链接逃逸。只读目录工具逐次审批、限制扫描量和返回条目数、不跟随目录链接。
- 模型提出 `write_file` 后，本地先检查路径和 UTF-8 文本内容，再逐项展示完整差异；提示明确标为“新建文件”或“覆盖已有文件”，只有本次输入 `y`、`yes` 或 `是` 才批准。多个独立单文件工具调用各自询问，不会沿用上一次确认；用户明确要求跨文件协调编辑时，只有 `apply_change_set` 会把 2–5 个精确补丁合并成一次整批预览与确认。EOF、Ctrl+C、拒绝或其他输入都不会写入。
- 需要局部编辑时，`read_file` 返回原始文件字节的 SHA-256。`patch_file` 要求调用方传入该哈希及精确、非空的 `old_text` 和 `new_text`；旧文本必须唯一匹配，不做模糊匹配或全局替换。单个替换片段最多 16 KiB，审批 diff 最多 32 KiB；拒绝敏感/内部/链接路径、终端控制或格式字符和超限文件。审批面板分开展示目标、由工具结构化提供的原文件 SHA-256 前 16 位指纹和差异；差异文本中的同名内容不能设置该可信指纹，模型/文件文本仍会脱敏。审批后版本变化会使本次审批失效。补丁使用原有备份、原子替换和 `/撤销`。
- 写入拒绝删除/清空已有文件、无效 UTF-8、NUL/控制字符二进制内容、超 64 KiB 内容、缺失父目录、链接路径、敏感路径和工作区外路径。已有文件的普通 POSIX `rwx` 位会保留；setuid/setgid/sticky 特殊位会清除并在审批差异中显示。POSIX 文件系统暴露的 ACL xattr 会复制；Windows 会复制原文件 DACL，并保留其受保护/允许继承状态，无法读取、设置或复核时取消替换。所有权、时间戳和其他扩展属性不承诺保留。
- 写入和撤销在准备同目录临时文件后，通过工作区相对目录句柄重读目标并核对字节、权限位及文件状态，再立即替换；Windows 也会在路径/reparse 检查后做最后一次版本核对，包含 DACL 内容及继承状态，以发现仅 ACL 变化。检测到冲突时目标不被替换/删除，原始备份保留，并把读取到的竞争版本原始字节（包括非 UTF-8 数据）写入备份记录；审批前发现外部修改时会先保存该快照再拒绝撤销。普通文件系统没有跨平台的“仅当版本仍匹配才替换”操作；最后一次核对到 `rename`/`os.replace` 之间仍有窄竞态，不能保证阻止非协作编辑器。advisory lock 不能为忽略锁的编辑器提供保证。`/撤销` 自身也需要单独预览和确认。
- POSIX 写入通过不跟随链接的目录文件描述符定位父目录；Windows 使用 reparse-point 检查和路径原子替换。两者的最后核对与替换之间都保留上述文件系统竞态；Windows 标准库也没有目录句柄相对替换接口。
- 文件读取、引用、目录列表、写入和撤销均由本地执行代码逐次检查；计划模式在工具层拒绝模型写入。工作区私有 `.harness/` 状态不能由模型工具改动，模型没有删除、shell 或任意代码执行工具。

实际修改时，在 `/模式 执行` 下直接描述单文件更改。整文件写入会显示新建/覆盖类型及完整 diff；局部补丁会分开展示目标、由工具结构化提供的原文件 SHA-256 前 16 位指纹和精确 diff，两者都等待本次单独确认。若用户要求一次协调修改 2–5 个已有文件，可使用上述 `apply_change_set` 一次审阅整批文件、路径、短哈希和完整差异，再确认一次。任一执行失败会停止后续文件写入，并尝试逆序恢复仍匹配本批版本的文件；`/变更集 列表` 查看中断批次，`/变更集 恢复 <编号>` 重新预览后单独确认。拒绝、冲突和恢复失败都逐文件报告；工作区外部变化不会被覆盖。该操作不提供跨文件原子事务，最后版本检查到替换之间仍有窄竞态。单文件写入/补丁可用 `/撤销` 并再次审阅差异确认。文件工具只编辑文本；不会自动运行或验证项目代码。`/测试 运行 <ID>` 仍由用户单独发起，每次测试执行和向模型分享其输出分别审批。
- 模型输出、文件内容、工具结果、目标文本和历史摘要都是不可信数据，不能修改权限规则。未知工具一律拒绝。
- 单次提问最多 4 轮模型回复、每轮最多执行 4 个工具调用、每个模型响应最多接收 16 个调用；输出预算默认 2048 个 provider completion tokens。按剩余请求槽分配每次 `max_tokens`；缺少 usage 时完整扣除该请求额度。重复调用编号、格式错误参数或超过单次额度的响应会在任何工具执行前终止当前轮次。
- 当前没有 shell、通用命令执行、隔离 worktree、PTC 执行或官方 Claude provider。Anthropic 消息协议只作为 DeepSeek 的兼容接口使用。子代理只允许两种只读工具，并且仅限用户预先批准的精确路径。
- Windows 路径/中文文件的普通读写测试在本机通过。当前 Debian 测试覆盖 symlink 与 hard link 逃逸；junction 和 Windows 链接策略由跨平台 CI 验证。测试不会更改系统链接权限。
